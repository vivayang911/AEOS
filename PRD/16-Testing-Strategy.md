# 测试策略

## 1. 测试层级

- 单元：规则、评分、PID、金额精度、状态机和 Schema。
- 集成：Attestcoin Adapter、数据库、队列、RPC、模型网关。
- 合约：单元、Fuzz、Invariant、Fork 和 gas 回归。
- 端到端：钱包登录、证据、决策、提案、投票、执行与复盘。
- 非功能：负载、故障注入、安全、可访问性和恢复演练。

## 2. 核心测试矩阵

| 场景 | 预期 |
|---|---|
| 合法证明 + 新鲜数据 | Evidence 可用于决策 |
| 无效证明/过期数据 | 隔离或阻断高影响建议 |
| Agent 引用不存在的 ID | Schema 后处理失败 |
| 策略超限 | 无法创建可执行提案 |
| 提案描述与 calldata 不符 | 构建/审批失败 |
| 重复执行请求 | 返回原结果，不重复交易 |
| 链重组 | 暂退状态并重新确认 |
| 暂停开启 | 只读可用、所有执行被拒绝 |
| 跨组织对象 ID | 404/拒绝且无信息泄漏 |

## 3. Agent 评估集

版本化黄金数据集包含可信、冲突、缺失、过期、恶意注入和极端数值样本。每次提示、模型、工具或检索变更运行离线评估；证据准确率、拒答、安全合规不得回退。

## 4. 测试环境

本地使用模拟 Attestcoin 与本地链；CI 使用确定性 fixtures；Staging 连接测试网和受限真实服务。生产数据默认不复制到测试环境。

## 5. 上线门禁

- 核心模块覆盖率 ≥ 80%，资金与权限逻辑分支覆盖率 ≥ 95%。
- E2E P0 流程全部通过。
- 无开放 Critical/High 安全问题。
- 合约 invariant、迁移演练、备份恢复和暂停演练通过。
- 可观测仪表盘、告警和运行手册已验证。
