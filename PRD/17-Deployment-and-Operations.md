# 部署与运维

## 1. 环境

- Local：Mock Provider、本地链、开发数据库。
- Dev：共享集成环境，使用测试密钥和测试网。
- Staging：生产同构、独立数据、发布验收。
- Production：强隔离、审批发布、Safe/KMS 和完整监控。

环境间不得共享数据库、私钥、会话密钥或链上管理角色。

## 2. CI/CD

1. 格式、类型、单元测试和依赖扫描。
2. 集成、Agent eval、合约 Fuzz/Invariant 和 E2E。
3. 构建带 SBOM 的签名镜像。
4. 部署 Staging，运行迁移检查与烟雾测试。
5. 人工批准生产；渐进发布；自动健康验证。
6. 应用回滚采用上一镜像；数据库优先前滚修复。

## 3. 可观测性

- Metrics：API 延迟/错误、队列积压、Agent 成功率/成本、Evidence 新鲜度、RPC 健康、执行确认。
- Logs：结构化、带 request/trace/decision/proposal ID，敏感字段脱敏。
- Traces：跨 API、Worker、Provider、LLM 和 RPC 链路。
- Audit：独立追加式业务审计流，不与普通日志混用。

## 4. SLO 与告警

- API 可用率 99.5%；关键读 P95 < 500 ms。
- Evidence 更新延迟按来源 SLA 设置；过期即告警。
- 执行失败、未知提案状态、权限变化和暂停均为高优先级告警。
- 错误预算耗尽时暂停非必要发布。

## 5. 备份与恢复

数据库每日全量 + 持续 WAL/PITR；对象存储版本化；配置和 IaC 版本控制。季度恢复演练，记录 RPO/RTO。链上状态可重建，但链下审批、快照和审计必须可靠备份。

## 6. 运行手册

必须包含：Attestcoin 不可用、RPC 分叉、Agent 队列阻塞、数据库故障、链重组、执行失败、密钥疑似泄漏和紧急暂停。每项定义检测信号、处置步骤、责任人和恢复验证。
