# RAG 与 Memory 设计

## 1. 知识分区

- Verified Evidence：结构化可信事实，最高优先级。
- Governance Knowledge：章程、策略、历史提案和会议记录。
- Protocol Knowledge：经过审核的协议文档与风险资料。
- Decision Memory：历史输入、结论、结果与复盘。
- Ephemeral Context：单次任务过程，不默认长期保存。

## 2. 摄取管道

文件/事件 → 恶意内容扫描 → 解析 → 保留标题与章节的分块 → 元数据与 ACL → 嵌入 → pgvector → 抽样质检。每个块记录来源、版本、有效期、组织和内容哈希。

## 3. 检索策略

1. 强制过滤 `organization_id`、文档状态和有效期。
2. 结构化证据先按链、资产和时间查询。
3. 文本资料使用关键词 + 向量混合检索。
4. reranker 按相关性、可信度和新鲜度排序。
5. 返回带稳定引用的有限上下文。

## 4. 记忆写入

只有经审批的结论、明确复盘和治理结果可以写入长期记忆。写入记录作者/审批者、来源和失效条件。自动抽取的“经验”先进入候选状态，不能直接影响高风险决策。

## 5. 防护

- 文档内容永远视为数据，不允许覆盖系统/工具规则。
- 检索服务不返回用户无权访问的片段或元数据。
- 删除按组织政策传播至原文、索引、缓存和备份生命周期。
- 对敏感信息在嵌入前脱敏；严禁嵌入私钥或访问令牌。

## 6. 评估

构建包含正常、无答案、冲突、跨组织和提示注入的黄金集；衡量 Recall@K、引用准确率、答案支持率、拒答质量、跨租户泄漏（目标 0）和检索延迟。
